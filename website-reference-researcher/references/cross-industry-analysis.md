# Cross-industry Analysis Method

## 1. 从设计问题选参考

先定义待解决的问题，再找网站。不要用“看起来高级”作为筛选标准。

至少记录：

```text
Research scope:
Current design problem:
Target audience and decision roles:
Primary conversion:
Site Communication Mode:
Purchase complexity / risk:
Trust required:
Available evidence and media:
```

`Site Communication Mode` 选最接近的一种，并可记录次要模式：

- Brand-led：优先建立理念、身份与长期记忆；
- Product-led：优先理解产品范围、差异和入口；
- Conversion-led：优先快速理解价值并采取行动；
- Content-platform：依赖持续发布的产品、技术、案例或活动内容；
- Hybrid：上述模式有明确主次地组合。

## 2. 跨行业相似性

按以下维度判断可迁移性，而不是只看行业标签：

- 用户需要先建立品牌信任，还是先筛选产品；
- 决策周期、金额、风险和参与角色是否相似；
- 证据主要来自产品、工厂、技术、文件、案例、人物还是规模；
- 内容关系属于解释、比较、浏览、过程、证明还是转化；
- 可用素材是普通图片、定制摄影、视频、3D、数据还是文件；
- 页面需要解决的是品牌命题、叙事节奏、媒体展示还是组件系统问题。

跨行业参考必须至少命中两个与当前问题相关的维度，并说明不相似之处。品牌知名度、预算和素材能力差距属于重要限制。

## 3. 候选池

默认建立 5–8 个候选，最终研究 3–5 个。优先组合：

```text
1–2 个同行：业务语言、买家问题和必需证据
1 个相邻行业：相似销售逻辑或信任建立方式
1 个品牌叙事参考：中心命题、内容取舍和页面节奏
1 个专项参考：Art Direction、媒体或关键模块
```

一个网站可以承担两个角色，但候选池不应全部来自同一审美类型。列表只展示网站、类型、拟解决的问题和一句推荐理由；用户确认前不做深度截图或 DOM/CSS 检查。用户明确给出最终限定名单时，该指令本身视为名单确认。

## 4. 六层分析

### Brand Narrative

- 希望访客记住什么；
- 页面在表达企业身份、客户价值还是未来议题；
- 产品与服务在品牌命题中的位置。

### Narrative Architecture

- 首屏提出什么；
- 页面如何从命题进入能力、证据、产品和行动；
- Section 强弱、Surface 和内容节奏如何变化。

### Content Editing

- 首页刻意展示、延后或删除了什么；
- 标题是栏目名称、利益、问题还是观点；
- 哪些信息被移到详情页、资源中心或导航。

### Page / Module Architecture

- 内容关系、扫读路径、主次与交互成本；
- Grid、Viewer、Tabs、Carousel、Timeline 等形式的内容理由；
- 桌面与移动端如何保持叙事，而不是只压窄布局。

### Art Direction

- 摄影、视频、3D、插画、图标和数据视觉的角色；
- 色温、视角、主体、裁切、动效与文字叠加方式；
- 当前项目是否具备相近的真实素材与制作能力。

### Visual System / DESIGN.md

- 色彩角色、排版、空间、Surface、形状、组件与状态；
- 哪些是跨页面规则，哪些只是 Campaign 特例；
- 第三方 `DESIGN.md` 的来源、覆盖范围、置信度与已知缺口。

## 5. 证据标签

- `Observed`：真实页面或可验证源码中直接看到；
- `Inferred`：由多个观察推导，必须写明推理依据；
- `Transferable`：适合当前问题，包含迁移理由和边界；
- `Not Transferable`：品牌、预算、素材、业务或用户任务不同，不应照搬；
- `Unavailable`：页面、状态或交互无法可靠访问。

同一结论可以同时标记 `Observed + Transferable`。`Inferred` 不能写成确定事实。

## 6. 迁移测试

每条建议至少回答：

1. 它解决当前哪个问题？
2. 为什么跨行业后仍成立？
3. 当前项目需要哪些内容或素材才能使用？
4. 哪个下游阶段负责最终决定？
5. 什么情况下应放弃这条建议？

只能回答“因为它好看”的建议应删除。
