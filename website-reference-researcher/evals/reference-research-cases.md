# Reference Research Cases

| Case | Expected behavior |
| --- | --- |
| PCB 同行业参考普遍目录化，用户希望提升品牌感 | 触发研究；候选同时包含 PCB/EMS、工业自动化或能源技术参考，并用决策、证据和素材角色解释跨行业迁移。 |
| 用户明确给出 4 个最终 URL | 直接研究这 4 个，不重复候选确认；仍分别标注参考角色和不可迁移内容。 |
| 只提供 Apple `DESIGN.md` | 将其作为辅助视觉证据；要求真实页面观察或明确证据限制，禁止直接成为项目 Design System。 |
| 网站无法访问或只捕获静态截图 | 标记 `Unavailable` 或具体缺口，不声称观察到 Hover、动效和响应式。 |
| 普通转化页目标、内容与视觉基线均清晰 | 跳过本 Skill，不为形式创建简报。 |
| 某个 Application 模块持续出现怪异交互 | 使用页面 + Section scope 生成模块级简报，不重做站点级研究。 |
| 站点级简报已存在且仍覆盖相同目标 | 复用简报；不重复浏览。目标、受众、Scope 或关键素材假设变化时才更新。 |
| 外站展示巨额 KPI、客户 Logo 或认证 | 只研究证据编排方法，不把外站事实写入当前企业资料或页面。 |
| Page Content 消费简报 | 只读取 Brand Narrative、Narrative Architecture、Content Editing 和证据策略，不采用外站视觉规则。 |
| Design System 消费简报 | 只读取 Art Direction、Visual System 和迁移边界，不复制品牌 token。 |
| UI Architecture 消费简报 | 只读取页面/模块、媒体、构图和响应式模式，不直接复刻外站 Section。 |
| HTML Prototyper 开始实现 | 不读取原始网站或 `DESIGN.md`，只继承已确认的 Design System、Map 和方向。 |
| 用户提供 Motion Sites 页面并希望企业站更有活力 | 记录可观察的 Trigger、对象、目的、频率、移动端与成本；只迁移能支持当前任务的机制，不复制专属视频、长距离 Sticky、滚轮劫持或品牌特效。 |
| 参考只有 Hero 截图但看起来“像有视差” | 标记 Motion 为 `Unavailable / Unknown`，不把视觉层叠推断成已观察到的滚动行为。 |
| 真实页面有多个自动播放视频 | 同时记录信息价值、加载与注意力成本；不能因动态强烈直接推荐给 B2B 项目。 |
| Motion 结论进入下游 | 跨页面运动性格交给 Design System，Section Trigger 与叙事模式交给 UI Architecture；不把具体 JS 实现交给两者。 |
| 三个同行首页都是左文右图 + 三列能力卡 | 记录为品类常见套路而非推荐基线；保留用户熟悉的导航与转化位置，但要求下游从企业真实对象和证据关系形成自己的首屏与整页主线。 |
| 跨行业网站很有设计感，但用户任务和证据类型不同 | 不因视觉冲击迁移；标记 `Not Transferable` 或只保留可证明适用的底层机制。 |
| 参考网站使用独特滚动装置且当前项目也想采用 | 记录它解决的理解问题、素材和运行成本、移动端与停止条件；把原品牌概念和专属动效列入 Similarity Risk，不直接复刻。 |
| 静态截图显示层叠画面，未实际操作页面 | 可以记录构图，不得把它写成滚动联动、视差或状态过渡证据。 |
