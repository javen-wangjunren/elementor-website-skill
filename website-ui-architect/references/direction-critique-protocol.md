# 方向稿独立评审协议

方向稿主要确认布局、模块顺序、信息层级和视觉方向，不是最终设计稿。HTML 阶段必须继续判断和精修，不能机械照抄图片。

## 什么时候触发

- 当前页面或模块生成、使用了 AI 方向稿图片：必须触发一次。
- 没有方向稿图片，直接从 Architecture Map 进入 HTML：跳过。
- 同一轮有多张分段方向稿：等当前设计范围完整后统一评审一次，不为每张图片分别派 Agent。
- 用户提供的是已经定稿、要求精准还原的设计稿：只检查可访问性、技术硬约束和还原风险，不重新设计。

## 子 Agent 介入时机

方向稿完成后、HTML 开始前，交给一个没有参与方向稿生成的全新子 Agent 独立检查。

提供给评审者：

- 已确认的页面内容或任务简报；
- Design System；
- Architecture Map 或当前模块方案；
- 实际方向稿图片；
- 必须遵守的业务、素材和真实性边界。

不要提供方向稿生成提示词、制作者的解释、历史评分或希望评审者得出的结论。

## 评审输出

1. **保留**：HTML 应继续继承的结构和特点。
2. **HTML 前必须修正**：页面任务、信息层级、证据位置、模块身份或整页节奏存在根本问题，必须先更新方案。
3. **交给 HTML 主动优化**：字体、换行、间距、密度、图片裁切、按钮位置等不应机械照抄的细节。
4. **忽略生图噪声**：错别字、轻微比例偏差和非权威装饰，不把它们误当成设计决定。

标准设计评审只做一轮，不打分。加强评审还要检查页面概念、整页视觉主线和品牌辨识度。

## 主 Agent 的责任

- 复核子 Agent 指出的问题，不能照单全收。
- 根本设计问题写回 Architecture Map 或页面方案。
- HTML 精修事项写入现有设计说明或 `visual-direction-notes.md`。
- 标准评审不单独创建长期报告。
- 无法调用独立子 Agent 时按同一清单自查，并明确标注“未完成独立方向评审”。
