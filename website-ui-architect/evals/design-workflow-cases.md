# Behavior Evaluation Cases

用于验证路径选择、设计门禁、方向稿停止条件、HTML Review 与 Pipeline 交接。表中“原 ID”对应瘦身前的 1–40 号用例，每项行为必须保留的行为不变量。

## 1. 上游输入与启动门禁

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 1 | 六模块 About 页已有 Page Content 和 Design System | 先判断方向稿和 HTML 路径，不在方向未确认时盲目生成 HTML。 |
| 2 | 用户提供参考图 | 说明保留的结构与品牌转换，默认只提供一个推荐方向。 |
| 3 | Hero、工厂等高视觉模块没有参考 | 方向真正不明时按需生成模块图片方向，确认后再生成 HTML。 |
| 7 | B2B 工厂、质检、证书或发货只有文字 | 报告关键素材缺口，不用图标、生成图或文字卡冒充真实证据。 |
| 8 | Design System、页面任务或真实内容不足 | 返回对应上游流程，不用通用模板填补。 |
| 21 | 只设计一个 Brief 明确的 Hero | 使用单模块 Brief，不强制整页 Architecture Map。 |

## 2. 单模块与 Pipeline 交接

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 4 | 用户确认当前模块方向 | 确定 Canonical Module Slug，只维护一个 `设计稿/modules/<module-slug>.html`，不默认生成命名卡或 QA 文档。 |
| 9 | 单模块 HTML 已确认 | 交付 HTML 与 Canonical Module Slug，不规划 Elementor 字段或同时实现多个 Widget。 |

## 3. 整页与逐模块路径

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 5 | 计划内模块均已确认 | 拼接整页，先执行 HTML Design Review，问题回写模块源，再执行 Browser QA。 |
| 6 | 只完成两个模块时查看整页 | 可更新临时拼接预览，不补写未设计模块。 |
| 10 | 整页图片方向成熟且结构清楚 | 可直接生成和精调整页 HTML，不强制独立模块文件。 |
| 11 | 模块内容密集、交互不同且需复用 | 推荐逐模块确认再拼接，不因有整页图就强制快速路径。 |
| 12 | 用户中途切换路径 | 允许切换；整页与模块稿并存时，Pipeline 前明确最终实现源。 |
| 13 | 用户确认方向后要求直接整页 HTML | 对 Section、相邻区域和整页做 HTML Review 与一轮修正，不强制逐模块用户门禁。 |

## 4. Architecture Map 与长页面

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 14 | 十模块首页生成方向稿 | 先生成并确认 Map，其中明确 Layout、媒体、CTA、Surface、衔接和降级；未确认不生图。 |
| 15 | 已确认 Map 包含十个 Section | 默认一张 Overview + 按叙事分组的分段稿，不把十模块压入一张画布。 |
| 20 | 只有五个 Section 的完整页 | 仍先确认 Map；若一张图能保持正常密度和比例，可不分段。 |

## 5. 素材比例与真实素材

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 16 | 产品、材料、Gallery、设备和证书没有特殊需求 | 优先使用契约默认比例，但不表述为不可更改。 |
| 17 | 方形产品、竖向设备或细长证书不适合默认比例 | 可调整，但 Map 必须记录默认/建议比例、理由、裁切策略和桌面/移动影响。 |
| 18 | 真实证书或设备无法合理裁入默认比例 | 先尝试 contain 或留白；仍不成立时建议调整并说明理由。 |

## 6. 方向稿审查与停止

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 19 | Section 被压缩、`4:3` 变 `3:1` 或出现虚构证据 | 视为 A 类明确问题，更新 Map 并自动修正受影响分段一轮。 |
| 22 | 三张分段稿已足以判断方向 | 立即停止生图，把精确比例和局部调整交给 HTML。 |
| 23 | `4:3` 略接近 `5:4` 或 `3:2` | 只要仍是正常横向构图且不影响判断，归为 C 类可接受偏差。 |
| 24 | 为追求精确比例准备批量追加独立模块图 | 识别为过度执行并停止；只有用户明确要求或构图仍无法判断时才新增。 |
| 38 | 同时存在错误主次、标题换行、近似比例和生成文字瑕疵 | 分别归为 A、B、C 类；不因 B/C 类重生整套方向稿。 |
| 40 | 三张分段稿只有第二段 Factory 结构错误 | 只更新对应 Map 和第二段一轮，不重生 Overview、其他分段或单模块图。 |

## 7. HTML 上下文审查与 QA 边界

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 25 | Hero 新增大背景、双 CTA 和 Partner Logos，后面紧接 KPI | 识别证据堆叠，先判断 KPI 删除、合并或迁移，不只换背景修饰。 |
| 26 | 短 KPI 被机械平均分成宽屏四列 | 根据真实信息几何收缩、合并或嵌入上下文，不把等分当成质量。 |
| 27 | Section 单独成立，但与前后重复构图、证据或重量 | 同时检查 Section、Neighbors 和 Full Page，不以局部无错结束。 |
| 28 | 一处是明确重复，另一处有多个合理 Gallery Layout | 前者自动修正一轮；后者向用户说明选项、理由和影响。 |
| 29 | 设计成立，但移动端溢出或 Tabs 键盘不可用 | 将设计审查与 Browser / Implementation QA 分开，两者都必须完成。 |

## 8. 真实渲染与模糊反馈

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 30 | 用户提供当前 HTML 局部截图 | 优先使用真实渲染证据并结合相邻 Section，不为仪式重复生成大量截图。 |
| 31 | 用户只能说“怪怪的”、“很挤”或“不协调” | 把感受转译为 1–3 个可验证原因，给出推荐方案、理由和影响。 |
| 32 | 模糊反馈出现在已确认的任务和 Design System 内 | 先定位最小问题范围，默认一个推荐修正；不静默重写内容或重开整页方向。 |

## 9. 模块逻辑回归

| 原 ID | 场景 | 必须行为 |
| --- | --- | --- |
| 33 | Map 字段完整，但未检查模块任务、证据关系和优先级 | 用户确认前执行 Module Design Review；形式完整不等于设计合格。 |
| 34 | Factory 五张同级证据被设计为永久一大四小 | 识别虚假层级；Viewer 可默认显示一项，但每项必须能切换到同等大图查看。 |
| 35 | 辅助型一站式服务 CTA 被评价为“单调” | 保持紧凑文字 + CTA，不强制增加背景图、大卡片或复杂动效。 |
| 36 | 核心产品或材料只用通用图 + 文字 List | 若识别和比较需要图像证据，改用可扫读的等权图片卡、Grid 或 Carousel；不让 Hover 成为唯一查看方式。 |
| 37 | `3:4` 或细长真实证书被压成小拼贴 | 保证文件形态和机构可辨认，提供等权大图、Carousel 或 Lightbox，不让列表挤压证据。 |
| 39 | 方向稿精准还原了 Map 的错误一大四小 | 仍判定不合格；Visual Review 同时检查 Map Fidelity 与 Module Fitness。 |

## 覆盖核对

原用例 `1–40` 在上述表格中每项恰好出现一次。后续新增回归时，优先在对应行为组中增加一行，不重新复制整套流程说明。
