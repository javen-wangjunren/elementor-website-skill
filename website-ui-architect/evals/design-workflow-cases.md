# Design Workflow Evaluation Cases

用于验证设计方案、媒体契约、生图与视觉交接；HTML 实现行为已迁移到 `website-html-prototyper`。下列生图审查场景只适用于已决定使用图片的范围，不把“修正图片”推广为所有 HTML 任务的必经步骤；文字方案确认可解决图片中的结构错误。

## 输入、Map 与方向图

| ID | 场景 | 必须行为 |
| --- | --- | --- |
| 1 | 六模块页面已有 Page Content 和 Design System | 先明确当前范围模块方案和可细化范围；图片按需，不编写 HTML。 |
| 2 | 用户提供参考图 | 说明保留结构与品牌转换，默认一个推荐方向。 |
| 3 | Hero、工厂等高视觉模块方向不明 | 按需生成模块方向图并等待确认。 |
| 7 | 工厂、质检、证书或发货只有文字 | 报告关键素材缺口，不用图标或生成图冒充真实证据。 |
| 8 | Design System、页面任务或真实内容不足 | 返回对应上游，不用通用模板填补。 |
| 14 | 十模块首页准备生成方向稿 | 粗图探索可依据模块范围和候选Map；进入HTML前确认模块方案，不先锁定图片尺寸等细节。 |
| 15 | 十个 Section 的 Map 已确认 | 方案已明确可直接交接HTML；用户要求整页图片时再按叙事分段生图，不默认补图或Overview。 |
| 16 | 常规产品、材料、Gallery、设备和证书 | 使用媒体契约建议比例，并允许有理由地调整。 |

| 19 | Section 被压缩、比例严重失真或出现虚构证据 | 判为A类、报告并先修正受影响方案；用户采用后直接HTML或按需生成局部Correction。 |
| 20 | 五个 Section 的完整页 | 需要图片时按叙事生成一个或多个Segment；若模块方案已确认且目标为HTML则直接交接。 |
| 21 | 只设计一个 Brief 明确的 Hero | 使用单模块 Brief，不强制整页 Map。 |
| 22 | Segment Set 已覆盖全部 Section 且结构和视觉均确认 | 停止生图，把实现精度交给 Prototyper。 |
| 23 | 方向图比例有轻微生成偏差但不影响判断 | 归为 C 类，不为像素精度重生。 |
| 24 | 准备为所有 Section 批量追加独立模块图 | 识别为过度执行；只有构图仍不清或用户要求时新增。 |

| 35 | 辅助型服务 CTA 被评价为“单调” | 保持紧凑表达，不强制加背景图、卡片或复杂动效。 |

| 38 | 同时存在错误主次、标题换行、近似比例和生成文字瑕疵 | 分为 A、B、C；A 先报告，获准后只补受影响 Section。 |
| 39 | 方向图精准还原 Map 的错误一大四小 | 仍不合格；同时检查 Map Fidelity 与 Module/Media Fitness。 |
| 40 | 只有第二段 Factory 结构错误 | 更新Factory方案，停止无效重试；采用方案后直接HTML或按需补局部图，其他模块不重开。 |
| 41 | 9 种 PCB、9 张可用 `4:3` 图 | 推荐图片主导等权 Gallery，记录视觉占比与桌面同屏数量。 |
| 42 | 9 种 PCB 只有低质量小图 | 可文字主导，但必须记录素材限制、最小尺寸和后续要求。 |
| 43 | 同组素材混有横、方、竖图 | 明确统一比例 + contain、分组或混用策略，不静默裁切。 |
| 44 | 5 张等权设备图 | 不形成永久一大四小。 |
| 45 | Map 写 `4:3`或用户明确后续使用真实产品照，精简卡片却把图片区改成小图标 | 保留有用产品查看面积，缺图按用途占位，不用外观证明内部层数；图标替换识别媒体判为 A 类 Media Fitness，先报告并按原门禁确认后只修受影响Section。 |
| 46 | 媒体布局有多个合理方向 | Product Design 可用时可 `ideate`；不可用时内部比较，不阻塞。 |
| 47 | Map 确认后真实素材审计发现比例冲突 | 只重新打开受影响 Section。 |
| 48 | S7 只有“四步横排 + 三个数据 + CTA” | 判定只有 Layout，在生图前补 Module Design Solution。 |
| 49 | S7 的 MOQ、报价、周期和检测证据绑定到节点 | 保持单一生产路径，不另建重复 KPI 行。 |
| 50 | 无图片流程模块 | 定义路径、数字层级等适合的表达；若步骤标题已能说明顺序，可省去重复描述并缩短模块，不保留原段落空位；必要条件仍可见。 |
| 51 | 信息很少的辅助模块 | 允许紧凑方案，说明主次与表达理由；任务已完成时，不为了填空增加照片、长文、标签或按钮。 |
| 52 | 从 Map 编译 Segment Prompt | 所有关键决定可追溯，无需临场决定卡片、证据或主次。 |
| 53 | 方向图还原 Layout 但丢失叙事或证据关系 | 判为 A 类 Solution Fidelity；只修受影响 Section，不自动重生整段。 |
| 54 | 相邻 Section 重复 KPI 或 CTA | 在 Map 阶段删除、合并、迁移或弱化。 |
| 55 | 完整页面有多个普通 Section | 方案紧凑写在同一 Map，不默认生成独立模块文档。 |
| 56 | 一个模块存在多个合理设计概念 | 比较信息策略、视觉叙事或 UI Composition，选定后回写 Map。 |

## Motion Contract 回归

| ID | 场景 | 必须行为 |
| --- | --- | --- |
| 83 | New Site / Rebuild 未特别说明动效 | 继承 Design System 的 `Restrained` Layer 1 基础反馈；普通 Section 省略 Motion 字段。没有被用户选择的显式 Layer 2/3 时，不创建 Page Motion Budget。 |
| 96 | Map 中发现一两个有价值的动态机会 | 作为 `Optional Motion Suggestions` 随原 Map 门禁提出；用户未选择时不进入 Motion Contract，也不阻塞页面设计。 |
| 84 | 用户说页面太静态、希望增加一点活力 | 只为受影响页面/Section补 Motion Intent；不让 Prototyper 临时创造动画，也不重开无关内容门禁。 |
| 85 | 首页有三个高动态候选 | 选择最多一个能解释核心价值或建立品牌记忆的 Signature，其余降级或移除，并记录 Page-level rejected motion。 |
| 86 | 普通内页没有动态叙事需要 | `Signature Moment: None`，只保留基础交互 Feedback。 |
| 87 | 方向图看起来像视差或视频 | 不把静态图片当作 Trigger、时间和滚动行为证据；以 Map Motion Intent 为权威。 |
| 88 | Layer 2 Reveal 覆盖全部 Section | Motion Fitness 不通过；只保留有顺序、叙事或数据表达价值的 Section，约 30%–50% 只是校准目标。 |
| 89 | Desktop Signature 在移动端成本过高 | Map 明确 Simplify 或 Remove，并提供保留内容和 CTA 的静态 fallback。 |
| 90 | 旧版确认 Map 没有 Motion 字段 | 不阻塞既有流程；未要求增强时只交接基础 Hover、Focus 和必要状态。 |
| 91 | 普通企业首页没有能解释核心价值的动态场景 | `Signature Moment: None`；Layer 3 不是首页必选项。 |
| 92 | 品牌型 About Us 只有团队图文 | 页面虽属候选类型，仍保持 Layer 1/2，不为页面类型强加 Signature。 |
| 93 | 活动页有明确品牌叙事与多阶段媒体联动 | 可确认最多一个 Layer 3，只写 Signature purpose、required behavior 与 mobile/reduced fallback。 |
| 94 | 普通服务页或产品列表页希望“更炫” | 默认不使用 Layer 3；只有可验证的解释需求才能重新进入候选。 |
| 95 | 核心产品详情页需让工作步骤与产品状态同步 | 可将对应 Section 设为 Layer 3 候选，但 UI Architect 只确认行为，不决定动画库。 |
| 114 | 新首页因高影响被标记为加强评审 | 盘点真实企业对象，形成 Distinctive Concept、Hero Structure、Page Visual Throughline 和 Whole-page Continuity；通过同行替换检验后再确认方案。 |
| 115 | 标准设计内页内容与结构清楚 | 不强制创建页面概念或 Signature；若使用方向稿图片仍须在 HTML 前完成一次独立方向评审，HTML 后继续标准评审。 |
| 116 | 首屏概念鲜明，后续全部是相同三列卡片 | Whole-page Continuity 不通过；只修正关键节点的叙事和节奏，不要求每个 Section 都做特殊构图。 |
| 117 | 两个方向只是换颜色、圆角和首屏图片 | 不算真实设计探索；必须从页面概念、信息策略、媒体关系、视觉叙事或浏览方式拉开差异。 |
| 118 | 关键页默认采用左文右图首屏 | 必须说明文字与媒体为何需要并列理解；没有理由时重新比较适合内容的 Hero Structure。 |
| 119 | 同行替换后页面概念仍完全成立 | 补入已确认的产品、工艺、文件、数据或场所特征；不得靠装饰、虚构事实或强动效制造差异。 |
| 120 | Tabs 的切换需要轻微过渡 | Motion Intent 标为 State Transition，说明目的和降级；不在 UI 阶段指定动画库和毫秒参数。 |
| 121 | 标准设计页生成了一组分段方向稿 | 当前范围完整后交给一个全新子 Agent 统一评审一次，不逐图派 Agent、不打分。 |
| 122 | 页面没有生成或使用方向稿图片 | 跳过方向稿独立评审，按确认 Map 进入 HTML。 |
| 123 | 用户提供定稿并要求精准还原 | 只检查可访问性、硬约束和还原风险，不借评审重新设计。 |

## 扫读与表达选择回归

| ID | 场景 | 必须行为 |
| --- | --- | --- |
| 100 | 四项短支持需同时比较，没有逐项配图需求 | 可保留清楚并列列表；不得因“静态平淡”强制折叠、补四图或自动切换。 |
| 101 | 用户选定单项展开与对应媒体 | 写清默认项、再次选择、图片/图注对应、手机与缺图处理；过渡可选，不以点击换图自动升级复杂动效或把单张检测图当四项证明。 |
| 102 | 强视觉首屏后接纯文字定义，用户认为突兀 | 结合直接相邻段检查重量与密度；允许留白、层次或解释图等方案，不强制所有定义配图，也不把辅助段做成第二首屏。 |
| 103 | 左右分别是组装服务与其他板型，缺少类别提示 | 用最短必要引导解释两组用途并贴近所属列表；不用新装饰替代分组，也不另加一轮内容审批。 |
| 104 | 参数表已可读，用户希望采用参考图的橙红表头 | 在本站规范内改风格，保留真实参数；不判原表必然结构失败，不把该配色推广成通用规则或复制参考数据。 |
| 105 | 定义、FAQ或复杂机制需要短段落解释 | 保留必要解释，优化标题、分段和对应媒体；不为追求“不读正文”把内容全部标签化或删去条件。 |
| 106 | 图上条目齐全，但分类/动作仍埋在长文，审查只复述Map | 根据实际可见重点判断扫读与主次，记录具体问题并按A/B/C处理；不能仅数条目判通过，也不要求另外生成报告。 |

| ID | 场景 | 必须行为 |

## 方向稿综合评估回归

| 场景 | 必须行为 |
| --- | --- |
| 用户只指出卡片文字多，图片中辅助模块还抢过核心模块 | 分开记用户反馈与 AI 观察，指出实际视觉竞争及影响，综合提出保留照片、精简文字和调整辅助模块重量的方案；不能只复述用户意见。 |
| 用户说“考虑用手风琴”，四条短内容需要同时比较 | 评估折叠对比较的代价，说明推荐；不把候选想法当锁定，也不把互动当成审美提升的必然条件。 |
| 用户明确保留照片，AI 偏爱图标 | 在照片约束内优化，不擅换图标；建议与要求分别记录，不把 AI 审美包装成事实。 |
| 图中表格清晰、用户认可，其他模块有问题 | 保留表格，只处理实际问题，不强制每段产生改动或评审表。 |
| 图片无法读取，但 Map 完整 | 说明未能看图；可继续评估方案，不能声称实际画面已通过。 |
| 用户已锁定精确比例，但 AI 觉得另一比例更美观 | 可以说明风险与建议，不自行改变比例或切换成粗方向模式。 |
