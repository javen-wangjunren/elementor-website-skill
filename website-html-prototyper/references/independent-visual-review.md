# 独立视觉评审：标准与加强

所有真正发生页面或模块设计的新建、重做和视觉精修，在 Browser QA 后都要完成标准设计评审。影响或风险较高的范围升级为加强评审。明确小改、纯内容替换、Bug 修复、固定法律模板和精准的小范围实现不触发设计评审。

## 评审层级与状态

```text
Quality Review Level: none | standard | enhanced
Quality Review Mode: independent | self-review-fallback | waived
Quality Review Status: not-required | checked | passed | failed | waived
Review Evidence:
```

### 标准设计评审

- 适用于每个真正发生设计或明显视觉调整的页面、模块。
- HTML First Draft 和 Browser QA 完成后，交给一个未参与制作的全新子 Agent 做一次盲审。
- 只提供桌面渲染、手机主要状态、页面任务、目标受众和硬约束；第一轮不提供源代码、制作理由、方向稿、历史评分或预设问题。
- 不打数字分，只做一轮。问题必须说明位置、可见证据、影响、严重度和建议，严重度使用 `P0–P3`。
- `P0/P1` 必须修正并由主 Agent 复核；完成后状态记为 `checked`。
- 默认不创建 `设计稿/reviews/` 目录，结论写入派工上下文或本次交付摘要。
- Existing Extension 按现站和已确认 Design System 检查延续性，不做脱离项目的通用审美评分。

### 加强评审

满足任一条件时升级：

- 会成为全站或同类页面的设计样板；
- 承担主要转化、信任建立或高流量入口；
- 使用新概念、独特视觉方式或进行重大改版；
- 包含复杂媒体、主要交互或显式动效；
- 设计不确定性高，或此前多次未达到预期。

加强评审从 `elementor-project.json.design.reviews` 读取目录；旧项目缺失时使用 `设计稿/reviews`，首次实际触发时创建 `设计稿/reviews/<page-slug>/`。证据至少包括桌面整页、手机主要状态、最高风险状态、同视口修改前后对比；动效优先使用状态序列图，确需判断正常速度手感时再录短视频。

评审维度按 10 分制：B2B 信息与下一步、信任证据、层级与整页节奏、品牌辨识度、媒体、桌面与手机、动效目的和细节完成度。通过条件是 `>= 8/10` 且没有 `P0/P1`，最多两轮。第二轮只复核原问题和直接副作用。存在主要 Tabs、Viewer、Carousel、Accordion 等交互时，再执行开放式交互走查。

## 问题回退

主 Agent 必须复现问题，不能照单全收：

- 页面概念、构图、媒体关系、动效目的 → UI Architect；
- 多处重复的视觉系统问题 → Design System；
- 换行、间距、裁切、timing、动画实现或浏览器问题 → Prototyper；
- Elementor 渲染、编辑器生命周期或多实例问题 → Widget Pipeline。

方向稿不提供给 HTML 第一轮盲审，避免评审者只检查“像不像图片”。主 Agent 在归因时再用 Architecture Map、锁定决定和方向稿结论核对。

## 用户反馈后的按需诊断

标准或加强评审完成后，用户仍可能针对某个模块的视觉或动效提出新反馈。此时不要一律追加子 Agent：

- 用户已给出明确、可执行的修改方向：直接按授权修改并检查受影响状态，不主动追加评审。
- 用户明确方向会改变 Motion Purpose、Layer、主要构图或交互关系：先由 UI Architect 把决定写回受影响方案，再实现；这属于设计边界确认，不等于必须调用评审子 Agent。
- 用户只表达“怪怪的、不好看、不顺、但说不清原因”，且修改方向不明确：主 Agent 主动询问一次，是否需要一个全新子 Agent 只诊断当前模块。用户同意后才派发，不能把可选诊断变成默认门禁。

按需诊断只提供当前模块的桌面/手机渲染、必要交互序列、模块任务和硬约束，不提供源码、制作辩护或希望得到的答案。输出包括：可观察问题、可能原因、2–3 个修改方向及取舍、推荐方向。它不打页面总分，也不替用户决定。

主 Agent 必须复现问题并综合判断。修改后只复查受影响模块、相邻模块和相关交互状态；只有主要构图、Motion Purpose、全局规则或页面主线发生变化时，才重新执行对应范围的标准或加强评审。

## 无独立子 Agent 时

标准评审可按同一清单自查，明确标记 `self-review-fallback` 与“未完成独立评审”，修正 P0/P1 后可记为 `checked`。加强评审的自查不能算独立通过；必须稍后完成独立评审，或由用户明确记录 `waived`。
