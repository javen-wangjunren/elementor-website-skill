# Browser / Implementation QA

在 HTML Design Review 通过后执行。使用真实浏览器验证可用性与实现稳定性；静态代码检查不能替代浏览器结论。

## 必查矩阵

### 视口与响应式

- 至少检查一个宽桌面、一个常规桌面/平板边界和一个窄移动视口。
- 检查横向溢出、内容截断、重叠、固定高度、异常留白和断点跳变。
- 验证 Map 中的移动端叙事：顺序、证据归属、CTA 可见性和媒体查看方式不能丢失。

### 真实内容与媒体

- 使用最终或代表性的最长标题、正文、标签、列表和 CTA；不只测试短占位文案。
- 检查图片、字体、图标、链接和本地资源均可加载；失败资源不得静默留下空框。
- 验证 `cover / contain`、焦点位置、替代文本、固有比例和高分辨率显示。
- 生成占位图必须继续标记为占位，不能在交接时变成真实证据。

### 语义与键盘

- 标题层级、Landmark、列表、按钮与链接语义合理。
- 所有可操作元素均可按自然顺序使用键盘到达和触发。
- Focus 清晰可见，不被 sticky 元素、裁切容器或动画遮挡。
- 不用不可聚焦的普通容器模拟按钮；图标按钮必须有可访问名称。

### 交互与状态

- Carousel、Tabs、Accordion、Lightbox、Viewer 等交互能操作，当前状态清楚，内容不会因 JS 失败而完全不可达。
- 链接目标、锚点、前后切换、关闭、边界状态和重复快速操作表现正确。
- Hover 不是获取关键信息的唯一方式；Touch 与键盘有等价路径。
- 表单仅在原型范围内验证标签、Focus、错误状态和基本提交反馈，不连接真实生产服务。

### Motion 与兼容

- 尊重 `prefers-reduced-motion`，移除非必要移动、自动播放或平滑滚动依赖。
- 禁用 JavaScript 时核心内容保持可见、可达；不能因初始化类缺失永久停在 `opacity: 0`。
- Layer 2 默认一次性观察并及时 `unobserve`；Layer 3 离开视口、页面隐藏或销毁时停止调度并清理监听。
- 不劫持滚轮，不以长距离 Sticky 阻塞阅读；连续视觉写入集中到一个 `requestAnimationFrame` 调度循环。
- 视频有 poster，非当前或离屏视频暂停；移动端按合同使用较轻素材、静态图或移除。
- 存在显式 Layer 2/3 时才对照 Page Motion Budget 检查动画数量、相邻运动焦点、重复 Reveal 和自动媒体竞争。
- 不依赖实验性特性完成核心阅读或操作；必要时提供降级。
- 检查控制台的阻塞错误，以及会影响内容、资源或交互的警告。

## 执行动作

1. 先记录基准视口与关键交互。
2. 对明确的实现缺陷做一轮最小修正。
3. 重新验证受影响视口、交互及相邻区域。
4. 若修正需要改变信息结构、核心构图或媒体契约，停止并返回 `website-ui-architect`。

## 输出

- 默认只在最终回复中给出简短 QA 结论、覆盖的关键视口/交互和仍存在的限制。
- 浏览器不可用、关键资源缺失或无法执行真实交互时，不得声称 Browser QA 通过。
- 不默认创建独立 QA 文件。
