# HTML Design Review

用于 HTML First Draft 生成后、Browser QA 之前的真实渲染审查。目标是确认实现忠实于已确认设计，并让真实内容在页面上下文中成立；不在此重新发明模块方案。执行时同时读取 [Visual QA Standard](visual-qa-standard.md)。

## 审查证据

1. 优先查看用户提供的当前 HTML 截图或现有浏览器渲染。
2. 否则在浏览器中查看整页、目标 Section 与前后相邻区域，并至少覆盖桌面与移动视口。
3. 浏览器不可用时只能做静态 HTML/CSS 检查，并明确说明视觉结论受限，不得声称已通过渲染审查。

## 审查顺序

先看 Full Page，再看 Section + Neighbors，最后看 Section。先建立整页基准，可避免只优化局部而破坏页面节奏。

### Section

- Section Job、Single Takeaway、证据归属和 CTA 是否与 Map 一致。
- Segment 定义的局部构图、视觉锚点、密度和媒体展示面积是否被正确实现。
- 真实文案、真实图片与比例变化后，是否仍可快速扫读。
- Motion 是否符合当前 Section 的 Purpose、Layer、Trigger 与 fallback；若为 None，不因页面“显得静”临时添加动画。

### Section + Neighbors

- 前后 Section 是否重复 Logo、KPI、CTA、卡片形式、Surface 或视觉焦点。
- 当前模块的高度、留白和媒体重量是否破坏相邻节奏。
- 证据是否仍靠近它所支撑的步骤或主张。
- 相邻 Section 是否出现重复 Reveal、多个运动焦点或自动媒体竞争。

### Full Page

- Architecture Map 定义的整体 Surface、明暗节奏和视觉重量是否在相邻 Segment 与真实页面中成立。
- 页面顺序是否继续服务访客的理解与决策路径。
- 局部实现是否造成整页单调、过密、断裂或多焦点竞争。
- 存在显式 Layer 2/3 时，Page Motion Budget 是否成立：动效帮助理解、状态、承接或单一品牌记忆，没有延迟核心内容或用同一种淡入覆盖全页；没有显式 Motion 时不补做审查字段。

## 模糊反馈诊断

用户说“怪怪的”“很挤”“很空”“很 Low”或“不协调”时，先结合当前渲染与相邻 Section，将感受转译为 1–3 个可观察原因，再给一个推荐修正及影响。不要要求用户先使用专业术语，也不要用换色、阴影或加卡片掩盖结构问题。

常见映射：

| 感受 | 优先检查 |
| --- | --- |
| 很挤 | 文案长度、行宽、间距层级、媒体占比、断点 |
| 很空 | 内容是否支撑当前面积、机械等分、无意义留白 |
| 很乱 | 对齐关系、强调手段、多焦点竞争 |
| 看不出重点 | 标题、数据、图片和 CTA 是否同时抢占最高层级 |
| 不协调 | Surface、密度、视觉重量与相邻模块的关系 |
| AI 感重 | 模板化卡片、虚构证据、无意义图标或装饰 |
| 太静态 | 先检查已确认 Motion Intent；缺失或需新增 Signature 属 A 类，已有意图但反馈不可见才属 B 类 |

## 问题分类

### A 类：设计源问题

Section Job、信息主次、证据归属、核心构图、媒体契约或响应式叙事需要改变。停止在 HTML 中重新设计，记录真实渲染证据并返回 `website-ui-architect`；只重新打开受影响 Section。

### B 类：实现适配问题

真实内容换行、间距、尺寸、对齐、精确裁切、断点、Focus、timing、位移、Observer、视频暂停或交互反馈偏差。可在 HTML 内自动修正一轮，随后重新查看受影响 Section 与相邻区域。

### C 类：可接受差异

不影响任务、可读性、证据、交互和响应式叙事的细微样式差异，不阻塞交付。

### D 类：系统规则验证失败

颜色角色、Surface、排版、间距尺度或共享组件规则在多个位置造成同类问题。记录完整页和代表 Section 的渲染证据，返回 `website-design-system-architect` 受控更新 Active Baseline。只有重复出现且根因属于共享规则时才归为 D 类；单页例外仍在页面层处理。

## 停止条件

- Review 是内部步骤，不默认创建评分表或独立报告。
- 一轮 B 类修正后重新渲染；若仍需改变设计决策，升级为 A 类并返回 Architect。
- 出现 D 类问题时停止局部打补丁；Design System 更新后重新渲染受影响页面，确认没有引入新的层级、对比度或组件一致性问题。
- 多个实现方案都忠实且差异只属审美偏好时，保留当前已确认方向，不持续自我重设。
- 用户已经接受当前模块时，不为追求像素级相似重新打开设计门禁。
