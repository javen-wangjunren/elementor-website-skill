# 动效手感与连续性标准

用于把 Design System 的 Motion Character 和 UI Map 的 Motion Intent 转成可实现、可验证的动作。它不创造新的动效目的，也不要求普通页面使用滚动叙事。

## 动作从哪里开始

- 操作反馈从用户触发的位置或被操作对象开始；按钮图标、指示器和目标内容之间要有清楚因果。
- Tabs、Accordion、Viewer、Carousel 的状态变化先让主对象响应，再让辅助文字、图标或背景跟随；不能让装饰先动、内容后到。
- 内容显现服从阅读顺序，但不把所有同级卡片机械排成长队。
- Scroll-linked 只有在滚动进度能解释工艺、流程、结构或媒体状态时采用；单纯“让页面更活”不构成理由。

## 开合与反向操作

- 打开与关闭应互为可理解的逆过程，起点、终点和状态含义一致；
- 用户在动画未结束前反向操作时，从当前视觉状态平滑转向新目标，不先跳回起点；
- 快速重复点击只保留一个最终状态，不残留半透明、错误高度、重复计时器或失去选中标记；
- 状态语义立即更新或按可访问性要求同步，不能等动画播完才让键盘和屏幕阅读器知道结果。

## 主次与先后

- 主对象先响应，辅助对象可稍后跟随，但延迟必须短且不影响理解；
- 同一状态切换只保留一个主要动作，其余元素以小幅度、低对比的方式配合；
- 相邻模块避免同时启动高注意力动作；自动媒体不能与用户正在操作的控件争夺焦点；
- 内容和 CTA 默认可见，动画是增强层，不是解锁阅读的门。

## 服从 Motion Character

- `Precise`：反馈迅速、位移短、终点清楚；
- `Damped`：允许轻微惯性感，但快速收住，不做反复弹跳；
- `Soft`：过渡平缓、幅度小，避免长时间拖尾；
- `Emphatic`：只在少数关键动作增加重量，普通控件仍保持克制。

优先使用 Design System Token。为了真实内容和浏览器表现调整 timing 或位移时，保持同一运动性格，并把调整归为实现层修正。不要通过新增动画库解决手感问题。

## 验证序列

对主要交互至少验证：

```text
初始状态 → 操作 A → 动画中反向操作 → 再次操作 A → 快速连续操作 → 最终状态
```

同时检查鼠标、键盘、Touch、Reduced Motion 和 JavaScript 失效。序列图或逐状态截图足以说明因果时不录视频；只有需要判断正常播放速度下的停点、力度或连续性时才录一段短视频。

## 不自动使用滚动叙事

滚动显现、Sticky、视差或滚动绑定不是落地页的默认配置。只有它们能解释真实过程、结构关系，或建立已经确认的关键品牌记忆时使用；否则保留自然滚动和即时状态反馈。
