# Visual QA Standard

用于 HTML First Draft 的真实渲染视觉审查。它补充 `html-design-review.md`，不替代已确认的 Design System、Architecture Map 或视觉方向。

## 判断模型

网页视觉没有唯一正确答案。审查使用互补的判断体系：

- 视觉层级：注意力顺序是否与业务优先级一致。
- Gestalt：接近、相似、共同区域、连续性和图形/背景是否正确表达关系。
- 内容—布局适配：构图是否适合用户任务、内容数量和素材比例。
- 色彩关系：语义、明度、饱和度、冷暖、面积、邻接与真实素材是否协调。
- 网格与排版：对齐、间距、行长、行高和跨断点重组是否稳定。
- 认知负荷：需要同时比较的内容是否被隐藏，交互成本是否与价值匹配。
- 可用性与无障碍：可读性、对比度、焦点和操作不能被审美牺牲。

规则可以排除明显错误，但不能证明某个方案是唯一最佳。主观方向冲突时保留已确认方向，或提供有限候选让用户决定。

## 必需证据

至少查看桌面与移动视口。完整页面任务应同时查看：

1. 彩色整页：品牌、情绪、模块节奏和主题跳变。
2. 灰度或降低色彩干扰的视图：明度层级和第一焦点。
3. 页面缩略视图：Surface 面积、重复构图和视觉重量分布。
4. Section 与前后邻居：边界、重复和叙事衔接。
5. 修改前后相同视口：验证改善，不凭记忆比较。

无法获得浏览器渲染时，不得声称视觉 QA 通过。

## 第一遍：整页

- 3 秒内能否识别页面主题、主要价值和主要行动？
- 一个视区内是否通常只有一个第一视觉焦点？
- 一个视区内是否同时存在多个运动焦点；运动是否改变了正确的注意力顺序？
- 高注意力颜色是否稀缺，还是按钮、标签、数字和装饰同时争抢？
- 相邻 Section 是否连续重复相同卡片、Surface、媒体比例或视觉重量？
- 深浅主题变化是否有内容或叙事理由？
- 页面是否像同一系统的连续体验，而不是模块模板拼接？

## 第二遍：Section 与布局

先回答 Section 的任务是解释、比较、浏览、深入探索、展示过程、提供证据还是促成行动，再判断布局。

| 任务 | 通常适合 | 风险形式 |
| --- | --- | --- |
| 解释单一价值 | 单焦点、文图双栏、大媒体配短文 | 多卡片、多 Tab |
| 同时比较 3–6 项 | 对齐列表、可扫描卡片、表格 | 轮播、逐项隐藏 |
| 浏览大量入口 | 分组网格、分类导航、View All | 一行塞满、过多窄 Tab |
| 深入探索少量场景 | 3–4 个始终可见选项、主从详情 | 只用箭头隐藏范围 |
| 展示过程 | 步骤流、时间线、递进叙事 | 无顺序的同质卡片 |
| 展示证据 | 尊重真实比例的陈列或数据带 | 把证书等素材强裁为统一卡片 |
| 单一转化 | 简洁 CTA、一个主按钮 | 多个同级高强调操作 |

每个 Section 检查：

- 主要目标和第一焦点是否一致。
- 内容是否能快速扫描，分组是否符合接近性和共同区域原则。
- 相同外观是否代表相同功能，不同功能是否被错误做成一样。
- 图片是证据、说明、氛围还是主角；展示面积和裁切是否匹配角色。
- 移动端是重新组织内容，还是只把桌面布局压窄。
- 动效在移动端是按合同保留、简化或移除，还是直接复制桌面成本。

需要改变 Section Job、主次、核心构图、媒体契约或响应式叙事时归 A 类；不要在 HTML 中私自重设方案。

## 第三遍：色彩

不要问孤立色相是否“搭配”。按以下顺序检查：

1. **角色**：品牌、文字、Surface、强调和状态颜色是否各司其职。
2. **明度**：灰度下背景、内容、重点和状态是否仍可区分。
3. **饱和度**：高饱和色是否集中在高优先级元素。
4. **面积**：强调色是否因大面积或高频重复失去强调能力。
5. **冷暖**：是否有稳定主调；冷暖双方是否无意中势均力敌。
6. **邻接**：实际相邻的文字、边框、控件和背景是否清晰协调。
7. **素材**：UI 是否与真实图片的亮度、色温和饱和度竞争。
8. **语义**：同一颜色是否被用于互相矛盾的含义。

`60–30–10` 只作为面积和主次的启发式，不测量精确像素，也不要求恰好三种色相。大面积通常低饱和，小面积才承担高强调。

普通文本对比度至少 `4.5:1`，大文本至少 `3:1`；关键非文本界面元素通常至少 `3:1`。达到对比度只说明可读，不代表配色协调。

## 第四遍：排版与空间

- 标题、正文、说明、数据和 CTA 是否有有限且清楚的层级。
- 长标题换行后是否失去重心；正文列宽和行高是否支持连续阅读。
- 同层级文字是否保持字号、字重、行高和色彩一致。
- 间距是否来自有限尺度，并用“组内小、组间大”表达关系。
- 留白是否帮助聚焦和分组，而非用空面积掩盖内容不足。
- 边框、阴影、圆角和容器是否过量；删除后若关系仍清楚，应优先简化。

## 问题输出

不得只说“Low”“更高级”“不协调”或“颜色不好看”。每个阻塞问题包含：

```markdown
### [P1] 问题标题
- 位置：
- 观察证据：
- 判断原则：
- 用户/页面影响：
- 建议：
- 验证方式：
- 分类：A / B / C / D
- 是否回写 Design System：是 / 否
```

严重程度：

- P0：影响理解、操作、可访问性或核心转化。
- P1：明显破坏层级、布局、页面节奏或系统一致性。
- P2：降低完成度，但不阻断理解和操作。
- P3：可选风格优化。

## 修正与停止

优先级为：内容和任务 → 信息架构与布局 → 层级与空间 → 色彩角色与面积 → 排版细节 → 功能性动效 → 装饰动效。结构不成立时，不用换色、阴影、新增卡片或动效掩盖。

- B 类明确问题自动修正一轮，并用相同视口重新验证。
- A 类返回 `website-ui-architect`，只重新打开受影响 Section。
- D 类携带重复位置和整页证据返回 `website-design-system-architect`，避免页面内反复打补丁。
- 多个实现都忠实、差异仅属个人偏好时，不持续自我重设。
- 用户确认当前方向后，不因追求主观完美无限迭代。
