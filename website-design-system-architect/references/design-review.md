# 设计师自查

## 定义与边界

设计师自查用于提高 Design Board 和 Active Baseline Design System 的首次交付质量。它不是 QA，不产生验收等级，也不检查响应式、溢出、浏览器兼容、性能、真实交互或生产实现。

模块 HTML 与整页 HTML 的实现 QA 属于 `website-ui-architect`。

## 自动修正规则

每个阶段只允许一轮自动修正：

1. 找出有充分证据的明显问题；
2. 一次性修正这些问题；
3. 重新快速核对受影响区域；
4. 若仍涉及品牌气质、审美偏好或业务优先级，停止自动调整并把具体选择交给用户。

不得用连续微调掩盖方向不确定，也不得把自查结果写成验收状态。交付时只说明“已完成设计自查”。

## Design Board Review

### 视觉证据优先级

1. 用户已提供完整 Board 截图：直接基于截图审查。
2. 否则使用 Ego Browser 渲染一次桌面整页作为视觉证据。使用前读取 `ego-browser` Skill；结束后清理本任务浏览器空间。
3. 浏览器不可用时检查 HTML 结构与 CSS，并说明视觉判断受限。

使用浏览器只为观察整页视觉组合，不做移动端、多视口、DOM/CSS、交互或兼容性 QA。

### 审查问题

- 整体气质是否统一，并符合目标行业、受众与已选方向？
- 色彩、字体、间距、圆角、边框和阴影是否属于同一视觉语言？
- Board 是否覆盖后续模块设计需要的常见基础组件？
- 示例是否符合真实网站使用方式，而非装饰性或古怪结构？
- Button、Card、List、Icon、Tabs、Accordion、Table 的层级与状态是否清晰？
- 是否存在卡片过大、比例失衡、强调色竞争、表格过重或方框序号？
- 是否误放了 Media、Responsive、页面区块或完整业务模块？
- UI Architect 是否仍需重新猜测基础规则？

若答案暴露明确问题，按自动修正规则处理一轮，再提交用户查看。

## Active Baseline Design System Review

正式交付前检查：

- 所有规则均可追溯到确认版 Board、用户决定或行业研究；
- 已确认的颜色角色、字体层级、间距、圆角与组件规则准确写入；
- `Locked / Flexible / Open` 完整，未确认项没有被写成 `Locked`；
- Board 未确认的 Media、Responsive、Motion、Accessibility 细节保留为 `Flexible` 或 `Open`；
- 未重新引入用户否决的模式，包括无圆角卡片、黑色重表头、方框序号 List、单张整行大卡片；
- 不包含页面布局、业务模块、Elementor 控件、PHP 类名或 CSS Selector；
- 规则之间无冲突，UI Architect 能直接据此设计模块。

明确遗漏、冲突或规则回退按自动修正规则处理一轮。仍需品牌或业务决定的内容保持 `Open`，不得擅自补齐。
