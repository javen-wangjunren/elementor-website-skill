# B2B 网站模块设计判断框架

## 核心结论

B2B 模块的质量，不由它单独看起来是否漂亮决定，而由它在当前页面环境中，是否以合适的信息量、证据和视觉重量，完成了应承担的商业任务。

```text
优秀的 B2B 模块
= 正确位置
+ 明确任务
+ 合适证据
+ 匹配的表达方式
+ 恰当的视觉重量
+ 与整页协调
```

这套框架的目的，是把原本存在于脑海中的隐性判断显性化，逐步将“这个模块好看”或“这个模块怪怪的”，转化成可解释、可比较、可修正、也可交给 AI 执行的设计判断。

## 1. 为什么不能只凭好看评价模块

模块是页面叙事中的一个句子，不是独立展示的海报。

一个模块可能单独看起来很精致，但如果它：

- 回答了错误的问题；
- 抢占了不属于它的注意力；
- 使用了不能证明结论的素材；
- 与前后模块重复；
- 让页面变得更长、更难理解；

那么它仍然不是一个合格的 B2B 模块。

相反，一个模块可能只有标题、一小段文字和一个 CTA，但如果它的任务只是让用户知道“我们也提供这项服务”，并引导有需要的人继续了解，那么它保持简单反而是正确设计。

### 一站式服务 CTA 案例

这个模块的任务不是完整证明公司的所有服务能力，而是辅助提示和导流。因此：

- 不需要用大幅背景图建立新的视觉中心；
- 不需要拆成多个卡片重复解释；
- 不需要因为“看起来单调”而提升为核心模块；
- 只需清楚说明服务价值，并提供合适的 CTA。

这个案例说明：

> 模块需要多少设计，取决于它承担多少任务，而不是取决于它还能增加多少元素。

## 2. 评价前先建立模块上下文

不先建立上下文，就不能准确评价模块。评价前先回答：

1. 这是什么页面？
2. 页面承担什么商业任务？
3. 模块处于访客决策过程的哪个阶段？
4. 它是核心证明、重要支撑、辅助说明、过渡，还是转化收口？
5. 访客看完后只需要记住什么？
6. 前后模块分别在讲什么？
7. 这个模块如果删除，页面是否仍能完成任务？

### 2.1 模块等级与视觉重量

| 模块等级 | 作用 | 合理的设计处理 |
| --- | --- | --- |
| 核心模块 | 回答页面主要问题 | 充分空间、强证据、清楚层级 |
| 重要支撑 | 建立能力、匹配度或信任 | 明确展示，但不抢主叙事 |
| 辅助说明 | 补充服务或次要信息 | 简洁、易扫读、控制高度 |
| 过渡模块 | 连接前后内容 | 减少独立焦点，引导阅读 |
| 转化模块 | 推动询价、下载或联系 | 利益和 CTA 明确，不重复解释全页 |

视觉重量应当跟随信息重要性，而不是跟随模板原有的效果。

## 3. B2B 模块的四层评价框架

四层必须按顺序检查。上一层明显不成立时，不应先用配色、圆角或动效修补。

### 3.1 第一层 商业任务

检查：

- 这个模块为什么存在？
- 它帮助访客确认什么？
- 它是介绍、解释、证明、比较，还是转化？
- 它是否服务当前页面的主要目标？
- 用户看完后是否知道下一步？

合格标准：

> 模块具有明确、必要，且适合当前位置的任务。

常见问题：

- 只因为同行有这个模块就加入页面；
- 一个模块同时承担太多任务；
- 次要信息获得核心模块的视觉重量；
- CTA 与当前内容没有逻辑关系；
- 模块没有回答任何新的访客问题；
- 一个内容更适合合并到相邻模块，却被强行独立。

### 3.2 第二层 证据结构

检查：

- 当前内容是企业自述，还是可验证的证据？
- 最适合的证据是图片、数据、文件、参数、流程、客户评价还是案例？
- 证据是否真实、具体，并与结论直接相关？
- 证据的显示尺寸是否足以查看？
- 证据是否可区分于装饰性素材？

合格标准：

> 模块使用了完成当前说服任务所需的最合适证据。

常见问题：

- 用图标代替产品、工厂、设备或证书；
- 用口号代替能力证明；
- 有证据，但尺寸小到无法阅读；
- 使用 AI 图片暗示真实工厂、设备或客户案例；
- 证据很多，但没有明确支持哪个结论；
- 重复使用同一张图片证明不同能力；
- 把应该保持真实比例的文件强行裁成卡片封面。

### 3.3 第三层 信息与构图

检查：

- 内容之间是并列、主从、过程、对比还是分类关系？
- 条目数量是否适合当前 Layout？
- 图片、文字和数据的面积是否匹配重要性？
- 用户是否能自然完成阅读？
- 与前后模块的构图和信息是否重复？
- 当前高度是否由内容决定，还是由模板决定？

合格标准：

> 构图让用户更快理解内容关系，而不是增加理解成本。

常见问题：

- 先选三栏卡片，再往里面填内容；
- 并列内容被强行做出无意义的主次；
- 信息很少，却占据一整屏；
- 内容很多，却被压进过小空间；
- 一张大图配多张小图，但没有内容理由说明大图更重要；
- 一组并列项目使用不一致的图片比例或高度；
- 连续多个模块重复左文右图、数字条或卡片网格；
- 为了填满画布而压缩模块高度或媒体比例；
- 为了“不单调”加入不产生证据价值的图片。

### 3.4 第四层 视觉细节

检查：

- 字体层级是否支持阅读顺序？
- 色彩是否符合已确认的角色？
- 圆角、边框和阴影是否属于同一语言？
- 留白是否支持层级，而非单纯增加高度？
- 图片比例和裁切是否保留主体？
- Hover 和动效是否提供状态反馈或信息价值？
- 移动端是否保留原有优先级？

合格标准：

> 视觉细节统一、清楚、克制，并强化前三层已经确定的信息关系。

常见问题：

- 用颜色、阴影和装饰掩盖结构问题；
- 标题、数据、说明和 CTA 同时争夺注意力；
- 信号色同时强调太多内容；
- 圆角、阴影和边框不统一；
- 字号太小、行长过长或信息过密；
- 所有内容都被放入独立容器；
- 动效只用来制造炫技感；
- 桌面构图到移动端退化成长串同质卡片。

## 4. 模块质量的综合判断

可以将模块质量理解为：

```text
模块质量
= 任务必要性
× 证据有效性
× 表达匹配度
× 页面协调性
× 视觉完成度
```

使用乘法而不是加法，是为了表达：任意一个底层条件明显不成立，都不能靠其他项的表面优势完全补救。

- 视觉精致不能补救错误的商业任务；
- 大量证据不能补救混乱的信息结构；
- 合理 Layout 不能补救虚构事实；
- 简单设计只要匹配任务，完全可以是优秀设计。

## 5. 常见 B2B 模块的合格标准

| 模块 | 主要回答的问题 | 优先证据 | 合理重量 | 常见问题 |
| --- | --- | --- | --- | --- |
| Hero | 你是谁，提供什么，我是否应该继续看？ | 明确定位、核心产品或场景、主 CTA | 高 | 文字过多、抽象口号、多个焦点、背景图无关 |
| 产品或材料分类 | 你们是否提供我需要的类型？ | 真实产品图、分类名、最小差异说明 | 高或中 | 只用 List、图标代替产品、卡片内文字过多 |
| 服务概览 | 你们能帮我做什么？ | 服务范围、成果、适用条件 | 取决于页面任务 | 把辅助服务做成核心大模块、每项都使用大图 |
| Why Choose Us | 这家供应商有什么值得选择的依据？ | 数据、现场、团队、能力与事实 | 中高 | 空泛优势、方框序号、长 List、与公司数据模块重复 |
| 公司数据 | 企业规模是否足以支撑交付？ | 经验年限、面积、人员、交付记录 | 中 | 无上下文的独立 KPI 带、数字缺少业务意义 |
| 工厂与设备 | 你们是否有真实生产和检测资源？ | 车间、生产线、设备、检测、仓储 | 高 | 一大四小无理由、图片太小、用第三方图暗示真实能力 |
| 质量与证书 | 质量体系和文件是否可验证？ | 证书、报告、可追溯文件、检测过程 | 中高 | 小图拼贴、图标卡片、文件不可点击放大、证书主体错误 |
| 流程 | 合作或生产如何推进？ | 步骤、输入、输出、节点责任 | 中 | 纯装饰时间线、步骤之间没有关系、过度解释 |
| 应用行业 | 你们是否理解我的应用环境？ | 行业场景、材料适配、应用约束 | 中高 | 通用图重复、只列行业名、暗示不存在的客户案例 |
| Case Study | 你们是否解决过类似问题？ | 背景、问题、行动、结果与可验证事实 | 高 | 只有客户 Logo、缺少结果、虚构数据、与作品集混淆 |
| Testimonials | 别人的真实体验是什么？ | 可验证身份、具体体验、合作上下文 | 中 | 泛化好评、虚构头像、轮播隐藏关键证据 |
| 技术资料与下载 | 我能否获取选型或采购所需资料？ | 数据表、目录、证书、报告、PDF | 中 | 用纯图标代替文件信息、文件名和版本不清楚 |
| 辅助 CTA | 如果我对这项内容有兴趣，去哪里继续了解？ | 简短利益、清楚去向 | 低或中 | 大幅图、过度解释、抢占主模块注意力 |
| Final CTA | 我接下来要提供什么，如何开始？ | 行动利益、所需资料、联系方式 | 中高 | 重复 Hero、多个同级 CTA、再次长篇介绍公司 |

## 6. 页面环境如何改变模块评价

同一个模块放在不同页面、不同位置，可能得到完全不同的判断。

### 6.1 页面任务不同

- 首页上的服务模块通常只需建立概览和导流；
- 服务详情页需要解释适用问题、能力边界、过程与证据；
- 产品页需要帮助选型，而不只是展示漂亮图片；
- About 页的工厂图用于证明真实性，Factory 页的同类图片则需要展开为具体资源。

### 6.2 页面位置不同

- 靠近页面开头的模块需要快速建立理解；
- 页面中段的模块需要增加证据和深度；
- 页面底部的模块需要收束信息并降低行动阻力；
- 两个强视觉模块连续出现时，后者可能需要收紧；
- 前一模块已经完成的证明，后一模块不应换个样式重复一遍。

### 6.3 内容数量不同

- 三个分类可能适合并排大卡；
- 八个产品形态更适合一次展示的目录网格；
- 五张等权设备图更适合 Viewer 或 Carousel；
- 三张证书可直接并排，更多文件则需要分类、分页或专门资料页。

因此，模块评审不能只看裁切后的单独截图，还需要看它在整页中的位置和前后关系。

## 7. 常见的跨模块设计问题

### 7.1 任务与视觉重量不匹配

- 辅助信息占据整屏；
- 核心证据被放在小卡片中；
- 简单 CTA 被设计成全页主视觉；
- 每个模块都试图成为页面焦点。

### 7.2 证据与表达方式不匹配

- 产品用文字 List，而不是产品图；
- 证书用图标表达，而不是真实文件；
- 工厂能力用数字代替现场证据；
- 需要比较的技术信息被写成长段落；
- 需要解释因果的流程只剩装饰性箭头。

### 7.3 信息几何与 Layout 不匹配

- 条目长短差异很大，却强行等高卡片；
- 图片主体是竖向设备，却固定使用超宽横条；
- 文件是 3:4 或 1:2，却裁成 16:9；
- 为了填满卡片而增加无价值文案；
- 为了对称而创造不存在的第四项或第六项。

### 7.4 卡片作为默认答案

卡片只适合表达真实的分组、边界或可点击对象。常见滥用包括：

- 每段文字都有独立边框；
- 简单数据被做成大面积卡片；
- 无关图标、序号和标签被加入卡片；
- 整个页面只剩下不同数量的网格。

### 7.5 只修饰当前模块，不检查整页

- 相邻模块重复信息；
- 相邻模块同时使用强背景和大图；
- 页面节奏一直紧张或一直平淡；
- CTA 密度过高；
- 单个模块优化后破坏了整页 Design System。

## 8. 如何正确使用模块库

[Section Express](https://get.section.express/) 将数千个 Elementor Blocks 按 Hero、CTA、Features、Gallery、Tabs、Carousel 等形式分类，也提供将多个 Block 组合成页面原型的工具。它很适合扩充 Layout 词汇，但不能替代页面和模块判断。

### 8.1 正确使用流程

```text
定义模块任务
→ 判断模块等级和视觉重量
→ 明确信息关系与证据类型
→ 在模块库寻找候选 Layout
→ 代入真实内容与素材
→ 使用四层框架检查
→ 放回整页上下文检查
→ 采用、简化、重组或放弃
```

### 8.2 不应该如何使用

- 看到漂亮模块就先收藏，再寻找安放位置；
- 根据模板名称直接代替模块任务分析；
- 为了使用某个 Layout 而增加内容；
- 将模板原有的高度、装饰和视觉重量原样带入项目；
- 认为付费模块或精致演示天然适合 B2B 页面；
- 只看单独截图，不看它与整页的关系。

模块库的正确定位是：

> 它是构图方案词典，不是设计答案库。

## 9. 模块 Design Review 实用模板

```text
页面：
页面任务：
模块位置：
前一模块：
后一模块：

模块任务：
模块等级：
访客应记住：
核心证据：
期望行动：

商业任务是否成立：
证据是否足够且可信：
构图是否匹配内容关系：
视觉重量是否匹配重要性：
与前后模块是否协调：
移动端是否保留相同优先级：

当前明确问题：
建议：
理由：
对整页的影响：
决定：保留 / 简化 / 重构 / 合并 / 删除
```

不建议只给模块一个综合分数。总分容易掩盖结构性问题，例如任务错误、事实虚构或证据无效。

### Review 的执行原则

```text
先查任务
→ 再查证据
→ 再查信息与构图
→ 最后查视觉细节
→ 放回整页复查
```

发现明确问题时，AI 可以自动修正一轮。当多个 Layout 都能合理完成任务时，应将选择交给人，而不是让 AI 持续重设。

## 10. 如何训练自己的模块审美

训练的目标不是背诵哪种风格更高级，而是更快判断模块为什么成立或不成立。

### 10.1 每周研究一种模块

```text
选择一种模块任务
→ 从真实 B2B 网站找 3 个案例
→ 从模块库找 3 个候选 Layout
→ 不先评价好不好看
→ 分别写出任务、证据、等级和上下文
→ 使用四层框架比较
→ 为一个具体页面选择最合适方案
→ 总结 1–3 条可复用原则
```

### 10.2 建立按任务分类的 Pattern Library

不按网站名收藏，而按模块任务整理：

```text
Hero
Product Category
Material Series
Service Overview
Factory and Equipment
Quality and Certificates
Why Choose Us
Process
Applications
Case Studies
Downloads
Supporting CTA
Final CTA
```

每个案例记录：

- 所在页面和位置；
- 模块任务；
- 信息量和素材数量；
- 使用的证据；
- 为什么 Layout 适合；
- 哪些元素不应照搬；
- 常见失败方式；
- 可迁移的原则。

### 10.3 练习将感觉翻译成设计语言

训练前：

> 这个模块感觉怪怪的。

训练后：

> 这是一个辅助服务提示，却获得了核心模块的高度和图片重量。图片没有增加证据价值，模块还打断了前后叙事，因此应简化为短文案和单一 CTA。

当能够稳定说明“任务、证据、构图、视觉重量和上下文”时，审美就不再只是个人好恶，而开始成为可交流的专业判断。

## 11. 最终原则

```text
优秀的 B2B 模块
不是视觉效果最多的模块，
而是在正确位置，
以恰当的视觉重量，
使用合适证据，
高效完成当前商业任务的模块。
```

这套框架不是要消除个人审美，而是先建立可解释的质量底线。在任务、证据、构图和上下文都成立之后，个人审美才用于在多个合理方案中做出更好的选择。
