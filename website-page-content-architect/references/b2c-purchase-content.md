# B2C 购买任务参考

只在页面承担直接购买或帮助选购任务时读取。补充通用内容方法，不建立新 Skill、不规定模块数量或顺序，不做 UI、购物车、账户、支付或后台开发。

## 检查购买问题有没有答案

- **商品发现与差异**：商品是什么、适合哪些场景、型号之间用哪些一致且可验证的字段比较；避免只有情绪口号。
- **价格与选择**：在承担报价/购买任务的入口呈现已知价格、币种和必要条件；可选配置、附加成本、库存或优惠不凭惯例补写。价格未确认时列缺口，不捏造真实售价。
- **下一步**：首页/聚合页提供相关详情、比较或选购帮助入口，详情页回答选择与购买条件；入口不等于要求本页展开全部资料或实现交易。
- **购买条件**：按当前商品风险检查配送、退换、保修、付款和支持需要哪些真实资料、在哪页说明；未知时列待确认要求，不套“免费配送、30 天退货”等通用承诺。

按实际任务保留需要的项，不对每页强制商品卡、比较表或全部政策段落。使用者、付款者或照护者是不同角色时，明确辅助说明，但不把使用者从主要叙事中移除。

## 演示与事实边界

- 用户明确允许视觉测试时，可使用中性演示名称、字段与价格验证文案长度；记录演示用途、需替换项与未验证范围，不冒充真实 SKU 或服务承诺。
- 没有演示授权且信息影响页面结构/公开主张时，只补问相关缺口；不追问与购买任务无关的产线、工厂或 MOQ。
- 生成图片只用于方向或演示，不能证明性能、尺寸、折叠、适航、车辆适配或使用安全；不编造评价、销量、认证和授权客户。
- 正式采用前核对真实商品及政策来源；测试文案不能因用户喜欢视觉就自动变成已核实业务事实。

## 交付边界

沿用页面目标、轻量 Section、缺口和 UI 移交格式。商品字段及价格条件放在对应页面文案，来源/未知项放在内容与素材要求；不要追加完整电商规范或内部检查报告。图文排版、页头和商品展示形式由 UI 决定。
