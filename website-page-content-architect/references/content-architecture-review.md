# Content Architecture Review

## 定义

交付页面内容框架前，从内容策略与信息架构角度检查一次，并自动修正一轮明确问题。它不是实现 QA，不检查视觉布局、响应式、HTML、SEO 配置或平台实现，也不输出验收等级。

## 1. 页面任务闭环

- 首屏是否快速说明页面是什么、适合谁、提供什么和下一步是什么？
- 模块组合是否足以完成页面承担的定位、匹配、说服、证明与转化任务？
- 是否覆盖目标客户真正关心的范围、能力、限制、证据、风险与行动？
- 页面结束时是否自然导向一个明确的主要转化？

## 2. 客户浏览顺序

- 顺序是否符合目标角色从业务匹配到比较、信任、顾虑处理再到行动的过程？
- 强证据是否出现在产生怀疑的位置，而不是全部堆到页面尾部？
- 访客是否需要先理解产品/服务，再理解公司优势或流程？若顺序相反，是否有业务依据？
- 相邻模块之间是否自然递进，而不是突然切换主题？

## 3. 模块质量

- 每个模块是否只承担一个主要决策任务？
- 是否有两个以上模块重复表达能力、质量、工厂实力、优势或 CTA？
- 是否因为素材尚未整理而错误删除产品、设备、认证、应用、案例或评价等重要模块？
- Case Study、Testimonials、客户 Logo、数据或认证模块是否按决策价值评估，而非默认删除或默认堆叠？
- 首页 Preview 与详情页职责是否清楚？
- `Core / Recommended / Optional` 是否反映模块对页面任务的真实价值？
- UI Architect 是否仍需重新猜模块目的、顺序或信息重点？

## 4. 文案可扫读性

- Heading 是否一眼可懂，直接说明主题或客户价值？
- 是否存在抽象口号、复杂隐喻、过度概念化或需要读第二遍的表述？
- Description 是否通常控制在 1–2 句，只表达一个核心意思？
- 是否能把长段落改成 3–6 个短列表、数据或并列项？
- Card title、列表项和 CTA 是否简短具体？
- 是否删除重复、自夸、空泛或无证据的修饰词？
- 访客仅扫描 Heading、数据、列表和 CTA 时，能否理解页面主线？

参考长度：Eyebrow 2–5 个英文词；Heading 优先 4–10 个词；Description 通常 18–40 个词；Card description 通常 12–28 个词；CTA 优先 2–5 个词。技术必要性可以突破，但必须保持直接。

## 5. 真实性与素材边界

- 模块需要的事实、图片、数据和证明是否写清楚？
- 素材待准备是否被正确记录，而没有被误判为结构阻塞？
- 案例、评价、客户、认证、设备参数和量化结果是否都等待真实资料，没有被 AI 补写？
- 只有会改变结构、主张或 CTA 的未知信息才进入用户确认项。

## 6. 自动修正与停止条件

1. 汇总明确的顺序错误、重复模块、关键缺口和冗长文案。
2. 一次性修正这些问题。
3. 重新快速检查整页任务闭环和可扫读性。
4. 若仍涉及业务策略、产品边界、主要转化或模块取舍，停止自动决定，向用户提出具体问题。

交付时只说明“已完成内容架构自查”。
